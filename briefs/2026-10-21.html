Eight eMudhra intermediate CA keys were so weak anyone could recover them and forge certificates for any domain

A researcher spotted it Oct 17 in public certificate data: per Mozilla's incident report the P-384 private keys, generated April 2025, had values under 256 (one was literally 4). eMudhra blames a key-generation script error and revoked them; Chrome, Firefox, Apple, Go and NSS shipped blocks and Cloudflare patched WARP, cloudflared and its CDN. No evidence of abuse found so far, but the keys were exposed for 18 months.

PHP ships emergency fixes today at 14:00 UTC for two critical bugs after details leaked early

CVE-2026-109618 and CVE-2026-109619 are rated CVSS 9.2 by PHP; watchTowr calls them CVSS 10 RCEs affecting PHP 5 through 8 and says it reproduced one. No in-the-wild exploitation seen yet, and PHP says it may release earlier if exploitation appears. Plan to patch this afternoon (16:00 Stockholm time).

TeamUpdraft breach: stolen UpdraftCentral connection keys already used to backdoor WordPress sites

TeamUpdraft (UpdraftPlus, 4M+ downloads) found unauthorised access Oct 17 to 18; the customer database held password hashes, 2FA settings and UpdraftCentral, Vault and Clone keys. Patchstack says backdooring of connected sites began Oct 18 at 15:32 UTC; roughly 10% of UpdraftPlus sites have such a key, up to about 400,000 sites. Rotate keys and reauthorize connections.

VectorsNew attack vectors & techniques

  • Weak-key CA failure: eMudhra's script generated a second set of weak keys that were picked for signing because their labels looked like the good ones; some were even cross-signed by Sectigo. A reminder that pinning and private trust stores need separate updates. Cloudflare
  • Release tampering without touching CI: the OVHcloud attacker uploaded locally built binaries to existing GitHub releases, so tests and CVE scans never ran. Enabling GitHub release immutability blocks this. BleepingComputer
  • Management-plane key theft: stolen UpdraftCentral keys let attackers send commands straight to connected WordPress sites, which Patchstack says may be worse than the earlier "wp2shell" wave. BleepingComputer
  • APT28 tradecraft shift: new Hookedge variants dropped free webhook.site tasking for a dedicated server for the most sensitive follow-up work, and the ld.exe payload only decrypts with a key given on the command line, so Symantec could not recover it. Symantec
